# โพลชุมชนของ Magga

แอดมินสร้างโพลที่ `/dashboard/admin/polls` ผู้เยี่ยมชมโหวตได้โดยไม่ต้องมีบัญชี ระบบใช้ PostgreSQL/Drizzle และ Asset Storage/R2 เดิม ไม่มีบริการฐานข้อมูลหรือระบบสมาชิกใหม่

## ก่อนเผยแพร่

1. ใช้ Bun 1.4.2 และ `bun install --frozen-lockfile`
2. สำรองฐานข้อมูลและตรวจ migration ค้างก่อนใช้ `bun run db:migrate` ตามกระบวนการเผยแพร่ของโปรเจกต์ Migration `0019_community_polls` เพิ่มเฉพาะตารางใน `private` และไม่แก้ข้อมูลมังงะหรือคอมเมนต์เดิม อย่าใช้ `db:push` กับ production
3. ใช้ `TURNSTILE_SECRET_KEY` และ `NEXT_PUBLIC_TURNSTILE_SITE_KEY` ของระบบเดิม โดย widget ต้องอนุญาต hostname ของ deployment การโหวตตรวจ action `poll_vote` ส่วนคอมเมนต์ยังใช้ `comment`
4. ตั้ง `POLL_ABUSE_SECRET` เป็นค่าสุ่มที่คงที่ (แนะนำอย่างน้อย 32 bytes) หากไม่ได้ตั้ง จะใช้ `BETTER_AUTH_SECRET` แทน ห้ามเปลี่ยน secret ระหว่างมีโพลเปิด เพราะใช้สร้าง HMAC ของสิทธิ์กันซ้ำและเครือข่าย การหมุน secret ต้องวางแผนปิดโพลเก่าและเริ่มโพลใหม่
5. Production ใช้ IP จาก `x-vercel-forwarded-for` ที่ Vercel กำหนดเท่านั้น หากย้าย hosting ต้องปรับ trusted ingress ก่อนเปิดโหวต ไม่เชื่อ `X-Forwarded-For` ที่ client ปลอมได้
6. ทดสอบโหวตจริงด้วย CAPTCHA บน hostname เป้าหมาย ทดสอบ token ซ้ำ การปิดตามเวลา และสิทธิ์แอดมิน ก่อนเปิดใช้งานสาธารณะ

## กติกา

- หนึ่งตัวตนมีหนึ่งบัตรต่อโพล เลือกหลายข้อยังเป็นหนึ่งบัตร
- ไม่มี fingerprint หรือ analytics identifier เป็นหลักฐานหลัก ผู้ไม่ยอมรับ analytics ยังโหวตได้
- Guest token สุ่มเก็บใน HttpOnly, SameSite=Lax cookie (Secure และ `__Host-` ใน production) อายุ 180 วัน ฝั่งฐานข้อมูลเก็บ SHA-256 ของ token
- เมื่อยืนยันได้ว่าบัญชีและ guest ใน browser เดียวกันเป็นผู้ใช้เดียวกัน จะผูกสิทธิ์เดิม ไม่เพิ่มบัตรใหม่ กรณีตัวตนทั้งสองมีคนละบัตรจะปฏิเสธและให้ผู้ดูแลตรวจสอบ
- โหมดมาตรฐานใช้ identity + CAPTCHA + rate limit โหมด IP จำกัดเครือข่ายร่วมกัน โหมดสมาชิกใช้บัญชีร่วมกับ guest claim
- การเปลี่ยนเครื่อง ล้าง cookie และเปลี่ยนเครือข่ายยังอาจหลบเลี่ยงโพลผู้เยี่ยมชมได้ CAPTCHA ไม่ใช่หลักฐานหนึ่งคนหนึ่งเสียง ใช้โหมดสมาชิกสำหรับโพลที่ต้องการความน่าเชื่อถือมากขึ้น
- เมื่อมีบัตรแล้ว ล็อกคำถาม รูปประกอบ ตัวเลือก เวลาเปิด จำนวนข้อ และกติกาการเปลี่ยนคำตอบ ใช้ทำสำเนาเมื่อต้องเปลี่ยนความหมาย
- เวลาปิดตรวจด้วย `clock_timestamp()` หลัง lock ใน transaction ไม่พึ่ง cron และไม่ยอมรับเวลาจาก client
- คำขอส่งซ้ำใช้ request UUID และ hash ของคำตอบ การตอบรับเดิมคืนได้แม้โพลปิดแล้ว แต่ไม่มีการเพิ่มบัตรหลังปิด
- ผลรวมคำนวณจากบัตรสถานะ `counted` โดยตรง ไม่มีช่องแก้คะแนน ยอดตัวเลือกและจำนวนบัตรอ่านจาก SQL statement เดียวกัน
- เปอร์เซ็นต์คือบัตรที่เลือกข้อนั้น / บัตรที่นับผลทั้งหมด โพลหลายข้ออาจรวมเกิน 100%
- ผลเฉพาะบุคคลและ API ทุกตัวใช้ private/no-store ไม่ฝังผลที่ซ่อนไว้ใน DTO สาธารณะ

## หน้าหลัก

อ่านข้อมูลใหม่จาก server ไม่ใช้ ISR ของโพล แสดงโพลสาธารณะที่เผยแพร่ เปิดอยู่ และเปิด “แสดงบนหน้าหลัก” เท่านั้น เลือกโพลที่ปักลำดับก่อน แล้วโพลเผยแพร่ล่าสุด แสดงครั้งละหนึ่งโพลพร้อมลิงก์รายการทั้งหมด หากไม่มีโพลจะ render `null` รวมทั้งไม่มี heading, wrapper, margin หรือ placeholder เพิ่ม โพลปิด พัก ตั้งเวลาที่ยังไม่ถึง ฉบับร่าง และ unlisted ไม่ปรากฏบนหน้าหลัก

## รูปภาพ

รับ JPEG, PNG, WebP ไม่เกิน 3 MB และ 20 ล้านพิกเซล แปลงเป็น WebP ลบ metadata และจำกัดด้านยาว 1600px รวมรูปอัปโหลดในโพลไม่เกิน 30 MB ตรวจเจ้าของไฟล์ก่อนแนบ และเลือกปกจากมังงะที่เผยแพร่แล้วได้

รูปฉบับร่างใช้ public R2 เช่นเดียวกับรูปเนื้อหาเดิม URL ที่รู้แล้วอาจเปิดได้ ฉบับร่างซ่อนหน้าและข้อมูล API แต่ไม่ได้รับประกันความลับของตัวไฟล์ หากต้องมีภาพลับต้องเพิ่ม private storage/proxy ก่อน

งาน `/api/cron/cleanup` เดิมจะล้างไฟล์โพลที่หมดอายุและไม่มีการอ้างอิง รวมถึง session และ rate limit ที่หมดอายุ การลบไฟล์ล้มเหลวจะเก็บ record retired ไว้ลองใหม่ ไม่มีการลบภาพที่มีโพลอ้างอิงอยู่

## การตรวจสอบและข้อจำกัดการใช้งาน

Dashboard ดูผล บัตรรายชั่วโมง 7 วันล่าสุด รายการบัตรหน้าละ 30 และประวัติการจัดการ 50 รายการล่าสุดได้ แสดงยอดคำขอที่ถูกปฏิเสธแยกตามเหตุผลใน 7 วัน โดยไม่บันทึกตัวตนของผู้ส่งในตัวนับเหล่านี้ และล้างตัวนับที่เก่ากว่า 90 วัน การลองส่งซ้ำหรือยืนยันหมดอายุไม่ใช่ข้อพิสูจน์ทุจริต การคัดออกหรือคืนบัตรต้องมีเหตุผล ไม่เปิดเผย IP หรือ hash ผู้โหวตผ่าน API dashboard CSV มีเฉพาะผลรวมและป้องกัน formula injection

ตอนเปิดโพล หน้าที่มองเห็นอัปเดตผลทุกประมาณ 15 วินาที หยุดเรียกเมื่อซ่อนแท็บหรือโพลปิด และลดความถี่เมื่อ provider ขัดข้อง การอ่านหน้าและการ refresh ยังมีค่า Vercel request/DB query ให้ติดตามปริมาณก่อนเปลี่ยนเป็น push

การรับบัตรใช้ row lock สั้นต่อโพลเพื่อรักษาความถูกต้องและประสานกับคำสั่งปิด ไม่เรียก CAPTCHA ภายใน transaction หากมีโพลที่รับบัตรพร้อมกันสูงมาก ต้องวัด lock latency และเพิ่มการแบ่งงานก่อนเพิ่มจำนวน connection

เมื่อพ้น 90 วันจากเวลาปิดและการแก้ไขล่าสุด งาน cleanup จะลบ claims และคำขอ retry ที่เชื่อมตัวตนกับบัตร โดยคงบัตรนิรนามและตัวเลือกไว้เพื่อรักษาผลรวมย้อนหลัง โพลที่ปิดแล้วแก้เวลาหรือเปิดซ้ำไม่ได้ Session หมดอายุที่ 180 วัน ประวัติการดำเนินการของแอดมินยังเก็บไว้ตรวจสอบ ไม่มีการนำข้อมูลโหวตไปใช้ analytics โดยอัตโนมัติ

โพลความคิดเห็น, รหัสเชิญ, โหวตซ้ำรายวัน, ranking และแจ้งเตือนอัตโนมัติยังเป็นส่วนต่อยอดตามแผน ไม่เปิดใช้ในรุ่นนี้

## ตรวจรับ

`bun run test` ใช้ฐานข้อมูล PGlite ใหม่ในไฟล์ทดสอบ ตรวจ migration, บัตรซ้ำ, retry, การเปลี่ยนคำตอบ, IP ร่วม, การผูก guest/member, visibility, deadline, version conflict, moderation, ownership รูป และการยุบหน้าหลัก ใช้ `bun run lint`, `bun run typecheck`, `bun run test` และ `bun run build:local` ก่อนเผยแพร่

หากย้อนกลับโค้ด ให้คงตารางโพลไว้เพื่อเก็บบัตรและประวัติ ห้าม drop ตารางหรือรีเซ็ตคะแนนเพื่อ rollback หน้าบ้าน
